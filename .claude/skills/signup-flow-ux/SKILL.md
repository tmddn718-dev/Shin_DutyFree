# 회원가입 플로우 UX 가이드

회원가입 화면을 만들거나 고칠 때 쓰는 범용 가이드다. 브랜드·컬러·카피는 프로젝트마다 바꾸고, **화면 구조·상태 설계·검증 방법**은 그대로 가져간다.

## 0. 시작 전: 바꿀 것과 유지할 것

| 바꿀 것 (프로젝트별) | 유지할 것 (재사용) |
|---|---|
| 디자인 토큰(컬러·폰트·라운드), 로고, 카피 | 5단계 화면 구조, 라우팅 방식 |
| 지원하는 간편가입·인증 수단 | 이메일/아이디 확인 상태 머신, 비밀번호 체크리스트 |
| 약관 항목·법적 문구 | 전체 동의 + 필수/선택 구분 + 펼침 구조 |
| 서버 API 응답 형식 | API 연결 지점(`config` 함수) 분리 |

- 디자인 시스템 문서가 있으면 **토큰만 CSS 변수로 옮긴다**. 참고한 다른 브랜드의 클래스명·로고·워드마크는 가져오지 않는다.
- 작업을 시작하면 요구사항을 아래 5단계에 매핑하고 위 표를 프로젝트 값으로 채운다.

## 1. 표준 화면 흐름

| 단계 | id | 내용 | 개선 포인트 |
|---|---|---|---|
| 1 | `entry` | 가입 방식 선택 | 혜택·방식별 설명으로 선택 이유 제시 |
| 2 | `verification` | 본인 인증 | 선택한 수단을 버튼 문구에 반영, 진행 상태 안내 |
| 3 | `info` | 정보 입력 | 필수 정보만, 실시간 검증으로 오류 예방 |
| 4 | `consent` | 약관 동의 | 필수/선택 시각 구분, 전체 동의 한 번 |
| 5 | `done` | 가입 완료 | 동의 현황 요약 + 다음 행동(서비스 시작) 연결 |

원칙:
- 화면당 **주 행동 1개**. 보조 행동은 시각적으로 낮춘다.
- 이미 아는 값(인증된 이름·휴대폰)은 다시 묻지 않고 자동으로 채운다.
- 주소처럼 가입에 꼭 필요하지 않은 항목은 **선택 항목**으로 두거나 가입 후로 미룬다.
- 단계 축소는 내용을 지우는 게 아니라 **합치는 것**이다. 결과 팝업은 완료 화면 요약으로, 부가 안내는 해당 단계 안의 목록으로 옮긴다.
- 버튼과 설명 캡션은 12px 이내로 붙여 한 그룹으로 읽히게 한다.
- 간편가입은 긴 텍스트 버튼 나열 대신 **원형 아이콘 + 짧은 라벨** 행으로.

## 2. 단일 HTML 프로토타입 구조

외부 UI 라이브러리 없이 `index.html` 하나(HTML+CSS+JS 인라인)로 만든다. 웹폰트·우편번호 검색 같은 CDN만 예외.

```js
const SCREENS = ["entry", "verification", "info", "consent", "done"];
function show(n) { SCREENS.forEach(s => document.getElementById("v-" + s).hidden = s !== n); }
function go(n) { show(n); history.pushState({ n }, "", "#" + n); }
addEventListener("popstate", e => show(e.state?.n ?? "entry"));
// [data-go="info"] 클릭 → go("info"), [data-back] 클릭 → history.back()
```

- 화면은 `<section id="v-{name}" hidden>`. `[hidden]{display:none!important}`를 넣어 화면별 `display` 지정이 `hidden`을 덮지 않게 한다. 래퍼 자체에는 `display`를 주지 않는다.
- 뒤로가기는 브라우저 뒤로가기와 같게 `pushState`/`popstate`로.
- 콘솔에서 `go('info')`로 바로 점프할 수 있게 `go`를 전역에 둔다.
- 실제 서버가 없는 프로토타입이면 실제 인증·조회를 한 것처럼 표현하지 않는다("시연용" 표기, 모의 응답).

## 3. 여러 사람의 화면을 한 파일로 합칠 때 (CSS/JS 충돌 방지)

- 화면마다 **고유 스코프**를 둔다: 화면 id(`#v-info`) + 접두어 클래스(`.si-…`) 또는 스코프 클래스(`.ev`, `.cs`). `.content`, `.caption`, `.btn`, `button` 같은 전역 셀렉터는 쓰지 않는다.
- 이름이 겹치면 더 구체적인 셀렉터로 덮기 전에 먼저 스코프로 분리한다. 부득이 덮을 때는 `#v-entry .content .caption`처럼 화면 id부터 시작한다.
- 한 화면용 높은 특이도 규칙이 다른 화면으로 번지는 사고가 잦다. 한 화면만 고칠 때는 `#v-화면id …` 규칙을 추가한다.
- 구 스타일을 보존해야 하면 `.cs`(신) / `.cs-old`(구)처럼 복제 분리하고 섞지 않는다.
- JS는 화면별 IIFE로 감싸고, 화면 간 통신은 `CustomEvent`(예: `signup:info-complete`, `detail`에 입력값)로 한다. iframe 안이면 `postMessage`로도 보낸다.
- 비밀번호는 `sessionStorage`·`localStorage`에 저장하지 않는다.
- 병합 후 각 화면을 375px에서 열어 간격·폰트가 병합 전과 같은지 `getBoundingClientRect()`로 실측한다.

## 4. 이메일/아이디 확인 상태 머신 (재가입 대응 포함)

"중복/사용 가능" 이진 판정 대신 상태를 나눈다.

```
idle → invalid(형식 오류) → checking → available | rejoin_available | unavailable
```

```js
const config = {
  // 프로토타입 모의 응답. 실서비스에서는 이 함수만 서버 호출(fetch)로 교체한다.
  checkEmail(email) {
    return new Promise(r => setTimeout(() => {
      const id = email.split("@")[0].toLowerCase();
      r(id.startsWith("rejoin") ? "rejoin_available"
        : id.startsWith("blocked") ? "unavailable" : "available");
    }, 700));
  },
  checkIdAvailable(id) { /* 모의: 예약어 목록(admin, test 등)과 비교 */ }
};
```

- 상태 `emailState = { status, checked, token }`. 값이 바뀌면 `checked = false`로 되돌려 **확인 완료를 무효화**한다.
- 연속 입력 시 오래된 응답 무시: 요청마다 `token`을 올리고, 응답의 `token`이 다르면 버린다.
- 다음 버튼 활성 조건 `isComplete()`에 `emailOk()`(available 또는 rejoin_available)를 포함한다.
- 버튼 라벨: `이메일 확인` → `확인 중` → `확인 완료` → (수정 시) `다시 확인`.
- 메시지는 기술 용어·비난 없이 **다음 행동을 알려 주는 문장**으로:
  - 사용할 수 있는 이메일이에요.
  - 이전에 사용한 이메일이에요. 다시 가입할 수 있어요. (오류가 아니라 성공 스타일)
  - 현재 이 이메일로 가입할 수 없어요. 다른 이메일을 사용해 주세요.
- ⚠️ 정책: 탈퇴·제재 등 **내부 사유를 노출하지 않는다**. 이메일 소유 확인 전 이력 노출은 계정 열거 위험이 있으므로 서버 정책과 함께 검토하고, 코드에 그 주석을 남긴다. 프론트 코드에 실제 이메일·회원 이력을 넣지 않는다.

## 5. 비밀번호·입력 UX

- 규칙은 제출 후 오류가 아니라 **입력 중 체크리스트**로 실시간 표시(길이·영문·숫자·특수문자). 충족 시 색 + 아이콘으로 바꾼다.
- 비밀번호 확인칸은 **확실히 틀렸을 때만** 오류: 값이 원래 비밀번호의 앞부분이면 입력 중으로 보고, 칸을 벗어났는데 다르거나 길이를 넘으면 "일치하지 않아요".
- 보기/숨기기 토글, `autocomplete="new-password"`, 숫자·이메일 필드는 `inputmode` 지정.
- 우편번호는 숫자 5자리 직접 입력 시 바로 검색, Enter·검색 버튼도 지원, 5자리 초과 입력 차단.
- 이메일은 붙여 넣은 `id@domain`을 아이디·도메인 칸으로 자동 분리.
- 오류는 필드 아래 한 줄, `aria-live="polite"` + 필드의 `aria-describedby`로 연결.

## 6. 약관·마케팅 동의

- **전체 동의**가 필수+선택을 한 번에 토글하고, 개별이 모두 체크되면 전체 동의도 자동 체크.
- 필수와 선택을 한눈에 구분: 필수는 강조 테두리·왼쪽 바·`필수` 배지, 동의 시 행 배경 변경 / 선택은 회색 면·얇은 테두리·`선택` 배지.
- 필수 미충족 시 하단 버튼 비활성 + "필수 동의 N개 남았어요"처럼 이유 표시.
- 상세 약관은 아코디언 또는 바텀시트. 체크박스가 많은 묶음(제휴 서비스 목록 등)은 대표 체크박스 하나로 묶고 펼쳐서 개별 선택.
- 마케팅 수신은 기본 해제, **채널(이메일·문자·우편·전화) × 주체(회사/서비스)** 표 하나로 모으고, 아래에 채널별 `동의/미동의` 요약을 보여 준다.
- 동의 결과 팝업을 여러 번 띄우지 말고 완료 화면의 **동의 현황 카드** 한 곳에서 보여 주며 "동의 내용 수정"으로 돌아갈 수 있게 한다.
- 약관 문구가 임시 값이면 README·화면에 명시한다.

## 7. 혜택 일러스트 스와이프 (선택 요소)

- flex 트랙 + `scroll-snap-type: x mandatory`, 슬라이드 `scroll-snap-stop: always`, 양끝 스페이서로 가운데 정렬. 자동 재생 없음.
- 슬라이드 폭 약 37%, 간격은 좁게. 트랙은 `position: relative`로 `offsetLeft` 기준 고정.
- 마우스는 pointer 이벤트 드래그(40px 이상 끌면 이전/다음).
- 인디케이터는 `go(i)`에서 직접 갱신한다. 미리보기 환경에서는 `scroll` 이벤트나 `scroll-behavior: smooth`가 동작하지 않을 수 있어 스크롤 이벤트에 의존하지 않는다.

## 8. 접근성·반응형 체크리스트

- 터치 타깃 ≥ 44×44px, 포커스 링 제거 금지, 버튼은 실제 `<button>`.
- 텍스트 대비 4.5:1 이상, 상태는 색 + 텍스트/아이콘 병행.
- 아이콘 버튼(간편가입 원형 버튼 포함)은 `aria-label` 필수.
- 기준 뷰포트 375×812, 360px에서도 가로 스크롤 없음. 데스크톱에서는 휴대폰 폭 프레임으로 보여 준다.
- `prefers-reduced-motion`에서 전환 애니메이션 최소화.

## 9. 작업·검증 절차

1. 요구사항 → 5단계 매핑, 0장 표 작성.
2. 레퍼런스는 비슷한 유형 3~5개만 보고 공통 패턴을 뽑는다.
3. 저장소 루트에서 `python3 -m http.server <포트>` 실행 후 `http://localhost:<포트>/index.html`. `file://`은 폰트·스크립트가 깨질 수 있다. 끝나면 서버를 끈다.
4. 375×812에서 확인하고, 끝나면 뷰포트를 되돌린다.
5. 상태 검증: 이메일 `rejoin…`/`blocked…`, 비밀번호 규칙, 약관 전체/개별 토글, 뒤로가기 순서. 스크립트로 입력할 때는 `input`/`change` 이벤트를 dispatch해야 상태가 갱신된다.
6. 간격·정렬은 눈대중 말고 `getBoundingClientRect()`로 px 확인. 스크린샷이 한 박자 늦을 수 있으니 상태는 JS로 교차 확인한다.
7. 개선 효과(시간 단축 등)는 사용성 테스트 전에 성과로 단정하지 않는다.

## 10. Git 작업 규칙

- 커밋·푸시는 **사용자가 요청할 때만**.
- 브랜치 이동 전 `git stash`, 이동 후 `git stash pop`.
- 푸시 전 `git fetch` → 필요하면 `git pull --rebase`(다른 사람·세션이 같은 브랜치에 푸시할 수 있다).
- "main에 적용" 요청은 **해당 화면 변경만** 옮긴다. 개편 브랜치 전체를 병합하지 않는다.
- 전체 UI 개편 실험은 별도 브랜치(`redesign/...`)에서 하고, 마음에 안 들면 `git revert`로 되돌린다.

## 11. 흔한 실수

| 증상 | 원인·해결 |
|---|---|
| 병합 후 한 화면 스타일이 다른 화면 간격을 깨뜨림 | 3장 스코프 규칙 |
| 화면이 겹쳐 보임 | `display`가 `hidden`을 덮음 → 2장 보강 CSS |
| 이메일 수정 후에도 "확인 완료" 유지 | 4장 `checked` 무효화 |
| 오래된 비동기 응답이 최신 상태를 덮음 | 4장 `token` 비교 |
| 비밀번호 확인칸이 입력 도중 빨갛게 됨 | 5장 앞부분 일치 처리 |
| 참고 서비스의 로고·클래스명이 섞여 들어감 | 브랜드 자산은 해당 프로젝트 것만 사용 |

## 12. 이 스킬 확장하기

새 프로젝트에서 찾은 패턴(다른 인증 수단, 새 약관 구조 등)은 해당 장에 추가하되 **특정 회사·프로젝트 고유 값은 넣지 않는다**. 화면 id·파일 구조·팀 브랜치 이름 같은 프로젝트 전용 규칙은 그 저장소의 `.claude/skills/`에 별도 스킬로 둔다.
