# UX 개선 반영 현황 (redesign/soft-clarity)

`DESIGN_SYSTEM.md`(Clear Journey)의 개선 기준을 `index.html`에 어떻게 반영했는지 정리한 문서입니다.
아래 내용은 **개선 가설과 구현 내용**이며, 효과(소요 시간·오류 감소 등)는 사용성 테스트 전에는 단정하지 않습니다.

## 화면별 반영

| 화면 | 반영한 것 |
| --- | --- |
| 가입 방식 | 방식별 카드(제목+설명+추가 인증 안내), 주요/보조 위계(파란 카드 vs 회색 카드), 외국인 가입 한·영 병기 |
| 본인 인증 | 인증별 준비물·소요 안내, 선택 카드, 선택 후 버튼 활성화, 선택한 수단이 버튼 문구에 반영 |
| 회원정보 | 묶음 제목(본인 인증 정보 / 계정 정보 / 추가 정보), 입력 전 조건 안내, 비밀번호 규칙 실시간 체크, 보기/숨기기, 주소는 선택 |
| 이메일 확인 | 6가지 상태(입력 전·형식 오류·확인 중·신규·재가입 가능·제한), 수정하면 확인 초기화, 오래된 응답 무시 |
| 약관 동의 | 필수(진행 `n/3`) → 선택 순서, 전체 동의는 상단의 평평한 한 줄(강조색 없이), 약관 보기 펼침, 마케팅은 동의 시에만 채널 설정 노출, 필수만 동의해도 가입 |
| 가입 완료 | 완료 메시지 우선, 계정 요약, 주 버튼 `신세계면세점 쇼핑 시작하기`, 서비스·동의 현황은 접기 |

## 공통

- **토큰:** 컬러·간격·라운드·모션을 `:root` 변수로 정의 (Primary `#246BFD`).
- **진행 표시:** 2~4단계 화면 상단에 얇은 진행 바 + `n/4 · 단계명`. 첫 화면(가입 방식)과 완료 화면에는 표시하지 않아요.
- **접근성:** `label` 연결, `aria-live` 메시지, `aria-invalid`, 포커스 링, `prefers-reduced-motion`, 터치 영역 44px 이상.
- **백엔드:** 같은 API(Supabase Edge Function). 주소가 비어 있으면 모의 응답.

## 반영하지 않았거나 확인이 필요한 것

- **파일 구조:** 문서의 다중 파일 구조(`pages/`, `css/`, `js/`) 대신 단일 `index.html` 프로토타입을 유지했습니다.
- **간편가입(카카오·앱카드):** 준비 중 안내만 표시합니다.
- **약관·혜택 문구:** 시연용 예시입니다. 실제 법적 문구와 혜택 정보로 교체해야 합니다.
- **탈퇴 이력 노출:** 이메일 소유 확인 전 이력 노출은 계정 열거 위험이 있어 운영 전 정책 검토가 필요합니다.
- **대비 검증:** WCAG AA 대비비 측정 도구로 확인하지 않았습니다.
- **주소 검색 모달:** 외부(Daum) 팝업이라 포커스 관리를 직접 하지 않았습니다.
- **사용성 테스트:** 아직 하지 않았습니다.

## UI 참고 (유아이볼)

라운즈(가입 방식 버튼·원형 SNS), 차란(평평한 약관 목록·`보기` 링크), 코오롱몰·증권앱(채워진 입력칸), 코빗·더벤티(완료 화면, 하단 고정 버튼, 이름 강조)를 참고해 카드 겹침을 줄이고 평평한 면과 얇은 구분선으로 바꿨어요. 컬러는 DESIGN_SYSTEM 그대로예요.
