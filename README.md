# Shin_DutyFree — 신세계면세점 회원가입 UX 개선

신세계포인트 × 신세계면세점 통합회원 가입 과정을 더 쉽게 만들기 위한 **모바일 UX 프로토타입**입니다.
`index.html` 한 파일로 동작하며, 실제 인증·가입은 진행되지 않습니다.

## Before / After: 8단계 → 5단계 (3단계 감소)

| STEP | Before (현재 회원가입) | After (개선 회원가입) | 변화 |
| --- | --- | --- | --- |
| 1 | 가입 방식 선택 | 가입 방식 선택 + **설명** | 개선 |
| 2 | 본인 인증 | 본인 인증 + **진행 안내** | 개선 |
| 3 | 회원정보 입력 | **필수 정보 입력** + **오류 예방** | 개선 |
| 4 | 주소 검색 | 필요할 때 추가 입력 | 선택으로 분리 |
| 5 | 약관·마케팅 동의 | **필수·선택 약관 구분** | 개선 |
| 6 | 동의 처리 팝업 | 제거 | 삭제 |
| 7 | 통합회원 계열사 안내 | 제거 | 삭제 |
| 8 | 면세점 가입 완료 | 가입 완료 + **쇼핑 연결** | 개선 |

- **필요할 때 추가 입력**: 주소, 마케팅 수신 채널 등은 필요성과 동의 여부에 따라 별도로 제공합니다.
- 단계 수는 8 → 5로 줄었지만, 줄어든 단계의 내용이 사라진 것은 아닙니다.
  - 동의 처리 팝업 2개는 가입 완료 화면의 동의 현황 목록으로 합쳤습니다.
  - 계열사 안내(통합 ID 서비스)는 약관 동의 화면 안의 체크박스 목록으로 옮겼습니다.
  - 주소는 정보 입력 화면의 선택 항목(비워도 다음으로 이동)으로 분리했습니다.

## 실행

빌드 없이 `index.html`을 브라우저에서 열면 됩니다. 데스크톱에서도 휴대폰 폭의 프레임으로 보입니다. 이때는 서버 없이 모의 응답으로 동작합니다.

### 백엔드와 함께 실행

```bash
python3 server.py            # http://localhost:8000
python3 server.py --port 8080 --db signup.db
```

Python 3.10 이상만 있으면 되고 설치할 패키지는 없습니다. 데이터는 SQLite 파일(`signup.db`, git에서 제외)에 저장됩니다.

| API | 설명 |
| --- | --- |
| `GET /api/health` | 서버 동작 확인 |
| `GET /api/users/check-id?userId=` | 아이디 중복확인 → `{available}` |
| `GET /api/users/check-nickname?nickname=` | 닉네임 중복확인 (한글·영문·숫자 2~10자, 대소문자 구분 없음) → `{available}` |
| `GET /api/users/check-referrer?userId=` | 추천인 아이디가 실제 회원인지 → `{exists}` |
| `POST /api/email/check` `{email, phone}` | 이메일 가입 가능 여부 → `{status: available \| returning \| rejoin_new \| unavailable}` |
| `POST /api/signup` | 정보입력 값(닉네임 포함) + 추천인(선택) + 약관 동의 저장 → `{userId, nickname, consentToken, memberType, firstJoinedAt}` |
| `POST /api/consents` `{consentToken, consents}` | 가입 완료 화면의 "동의 내용 수정" 저장 (토큰은 가입 후 30분 유효) |

### Supabase로 실행 (server.py 대신)

같은 API를 Supabase(Postgres + Auth + Edge Function)로 옮겼습니다. 화면 코드는 그대로이고 주소만 바뀝니다.

```bash
supabase link --project-ref <프로젝트 ref>
supabase db push                          # supabase/migrations 의 스키마 적용
psql "$DB_URL" -f supabase/seed.sql       # 시연용 데이터(데모 프로젝트에서만)
supabase functions deploy api             # supabase/functions/api
supabase secrets set ALLOWED_ORIGIN=https://배포주소   # 선택. 비우면 모든 주소 허용
```

그다음 `index.html` 의 `<meta name="signup-api-base" content="">` 에 `https://<프로젝트 ref>.supabase.co/functions/v1/api` 를 넣으면 됩니다. 비워 두면 예전처럼 `server.py` 또는 모의 응답으로 동작합니다.

- **비밀번호:** Supabase Auth 가 해시해 보관합니다. 테이블에는 비밀번호가 없고 `members.auth_id` 로 연결됩니다.
- **접근 제한:** 모든 테이블은 RLS 를 켜고 정책을 만들지 않았습니다. 브라우저는 테이블에 직접 접근하지 못하고 Edge Function(service role)만 읽고 씁니다. `SUPABASE_SERVICE_ROLE_KEY` 는 화면 코드에 넣지 않습니다.
- **복귀/신규 판단:** `email_status()` SQL 함수 한 곳에서 합니다. 이메일 확인 API 와 가입 처리가 같은 함수를 씁니다.
- **가입 처리:** `create_member()` 가 회원과 동의를 한 트랜잭션으로 저장합니다. 저장이 실패하면 방금 만든 Auth 계정도 지웁니다.
- **아직 옮기지 않은 것:** 간편가입(OAuth)입니다. Supabase 에서는 버튼이 안내 문구만 보여 줍니다. 필요하면 Supabase Auth 의 카카오 로그인으로 따로 이어야 합니다.
- **검증:** `node --test supabase/functions/api/rules.test.ts` (입력 규칙 테스트, Node 22.6+). SQL 과 Edge Function 은 이 환경에 Postgres/Deno 가 없어 실행해 보지 못했습니다. 배포 후 `GET .../health` 부터 확인하세요.

### 간편가입 (OAuth, 가입만)

카카오 버튼을 누르면 OAuth 2.0 인가 코드 방식으로 제공자 계정을 받아 오고, 이어서 본인인증 → 정보 입력 → 약관 동의를 거쳐 가입합니다. **지금은 가입만** 다루고 로그인·세션은 없습니다.

```
카카오 버튼 → GET /api/auth/kakao/start      (state 를 서버와 쿠키에 저장, 제공자 로그인 화면으로)
          → 제공자 로그인·동의
          → GET /api/auth/kakao/callback     (state 확인 → 코드로 토큰 → 프로필)
          → /#social=티켓                    (30분짜리 1회용 가입 티켓, 주소창에서 바로 지움)
          → POST /api/auth/ticket            (티켓으로 이메일·닉네임을 받아 정보 입력에 채움)
          → POST /api/signup {socialTicket}  (아이디·비밀번호 없이 가입, 제공자 계정을 연결하고 티켓 사용 처리)
```

| API | 설명 |
| --- | --- |
| `GET /api/auth/providers` | 제공자 목록과 모드(`live` 키 있음 / `demo` 키 없음) |
| `GET /api/auth/{provider}/start` | 제공자 로그인 화면으로 이동 |
| `GET /api/auth/{provider}/callback` | 제공자가 돌려보내는 주소. 실패하면 `/#social_error=denied·state·provider·already` |
| `POST /api/auth/ticket` `{ticket}` | 티켓의 프로필 → `{provider, providerName, email, emailVerified, nickname}` |

- **키 넣는 곳:** `.env.example`을 `.env`로 복사해 `OAUTH_KAKAO_CLIENT_ID` 등을 채웁니다. `.env`는 git에 올라가지 않습니다. 제공자 개발자 센터에는 redirect URI로 `PUBLIC_BASE_URL/api/auth/kakao/callback`(기본 `http://localhost:8000/api/auth/kakao/callback`)을 등록하세요.
- **키가 없으면 시연 모드:** 제공자 화면 없이 바로 콜백으로 돌아와 가짜 프로필(`kakao1a2b3c@example.com` 등)로 같은 흐름을 진행합니다. 서버를 켤 때 제공자별 모드를 출력합니다.
- **제공자 늘리기:** `server.py`의 `OAUTH_PROVIDERS`에 카카오·네이버·구글이 들어 있습니다. 화면에는 카카오 버튼만 있고, 다른 제공자는 `data-oauth="naver"` 같은 버튼만 추가하면 됩니다. 앱카드는 OAuth가 아니라 그대로 "준비 중"입니다.
- 간편가입 회원은 내부 아이디(`kakao` + 난수)를 자동으로 받고 비밀번호는 없습니다. 같은 제공자 계정으로 두 번 가입할 수 없습니다.
- 본인인증, 닉네임 중복확인, 탈퇴 이메일 처리, 추천인, 약관 동의는 일반 가입과 똑같이 거칩니다.

### 탈퇴한 이메일로 다시 가입할 때

이메일을 입력하면 "탈퇴한 이메일이에요."라고 먼저 알려 주고, 본인인증한 휴대폰으로 같은 사람인지 확인해 처리합니다.

| 조건 | 응답 | 처리 |
| --- | --- | --- |
| 탈퇴 회원과 휴대폰이 같고 탈퇴 후 30일 이내 | `returning` (`daysLeft` 포함) | 기존 회원으로 복귀. 탈퇴 전 가입일을 이어서 씀 (`memberType: returning`) |
| 휴대폰은 같지만 30일이 지남 | `rejoin_new` + `reason: expired` | 신규 회원 |
| 휴대폰이 다름 | `rejoin_new` (사유 없음) | 신규 회원. 다른 사람에게 탈퇴 시점을 드러내지 않음 |

복귀 여부는 화면이 보낸 값이 아니라 가입 요청 때 서버가 다시 계산합니다.

### 닉네임 · 추천인

- 닉네임: 정보 입력 화면의 비밀번호 확인 바로 아래. 필수이며 중복확인을 통과해야 다음으로 넘어갑니다.
- 추천인: 약관 동의 화면의 선택 항목 바로 아래. 선택이며, 입력했다면 "확인"을 누르거나 가입 버튼을 누를 때 실제 회원인지 확인합니다. 본인 아이디는 넣을 수 없고, 가입 후 "동의 내용 수정"에서는 바꿀 수 없습니다.

### 그 밖의 처리

- 비밀번호는 scrypt로 해시해 저장하고, 로그에는 요청 경로만 남깁니다.
- 이미 가입된 이메일과 가입 제한 이메일은 같은 `unavailable`로 응답해 사유를 드러내지 않습니다.
- 서버는 `index.html`만 제공하고 DB 파일 등 다른 파일은 노출하지 않습니다.
- 이메일은 소문자로, 휴대폰은 `010-1234-5678` 형태로 맞춰 저장합니다. 서비스 이름은 정해진 9개만 받습니다.
- 잘못된 요청(JSON 배열, UTF-8이 아닌 본문, 잘못된 `Content-Length` 등)은 500이 아니라 400으로 답합니다.
- 예전에 만든 `signup.db`도 그대로 쓸 수 있습니다. 서버를 켤 때 새 컬럼을 자동으로 추가합니다.

### 시연용 데이터

| 값 | 결과 |
| --- | --- |
| 아이디 `admin`·`shinsegae`·`test1234`·`gudals4360`·`friend1234` | 이미 사용 중 |
| 닉네임 `관리자`·`운영자`·`admin`·`신세계`·`친구` | 이미 사용 중 |
| 추천인 `friend1234` | 있는 회원 (그 외는 "찾을 수 없어요") |
| 이메일 `rejoin@example.com` | 탈퇴 10일째 → 기존 회원으로 복귀 (시연용 휴대폰 `010-1234-5678` 기준) |
| 이메일 `old@example.com` | 탈퇴 45일째 → 신규 회원 |
| 이메일 `blocked@example.com` | 가입 제한 |

탈퇴 날짜는 서버를 켤 때마다 그 시점 기준으로 다시 넣습니다. 한 번 가입에 쓴 이메일은 이미 가입된 이메일이 되므로, 처음부터 다시 해 보려면 서버를 끄고 `signup.db`를 지운 뒤 다시 켜세요. 서버 없이 `index.html`만 열면 이메일 아이디가 `rejoin`·`old`·`blocked`로 시작하는지로 같은 결과를 흉내 냅니다.

- 본인인증·이메일 소유 확인은 하지 않는 시연용 서버입니다.

- 글꼴(Pretendard)과 주소 검색(다음 우편번호)은 인터넷에서 불러옵니다. 오프라인에서는 기본 글꼴로 보이고 주소 검색은 동작하지 않습니다.

## 가입 흐름 (4단계)

| 단계 | 화면 | 내용 |
| --- | --- | --- |
| 1/4 | 가입 방식 선택 | 통합회원 가입, 외국인 가입, 카카오·앱카드 간편가입 선택. 가입 혜택 캐러셀 안내 |
| 2/4 | 본인 인증 | 휴대폰 · 신한인증서 · 카드 인증 중 선택 (시연용으로 실제 인증 없이 이동) |
| 3/4 | 정보 입력 | 아이디(중복확인), 비밀번호 규칙 체크, 닉네임(중복확인), 이름·휴대폰(인증값), 이메일(탈퇴 이메일 안내), 자택주소(선택) |
| 4/4 | 약관 동의 → 가입 완료 | 아래 "약관 동의 개선" 참고 |

화면 상단의 진행 표시는 위 5단계 중 "필수 정보 입력"까지를 1~3, 약관 동의와 완료를 4로 묶어 `n/4`로 보여 줍니다. 각 단계의 추가 요소(1단계 설명, 2단계 진행 안내, 3단계 오류 예방, 5단계 쇼핑 연결)는 화면에 이렇게 들어 있습니다.

- 가입 방식 선택: 혜택 캐러셀과 방식별 캡션으로 선택 이유를 설명
- 본인 인증: 선택한 방법을 버튼 문구에 반영하고 이동 중 토스트로 진행 상황 안내
- 정보 입력: 아이디 중복확인, 비밀번호 규칙 실시간 체크, 이메일 자동 분리 등으로 입력 오류를 미리 방지
- 가입 완료: "쇼핑 시작하기" 버튼으로 쇼핑에 바로 연결

가입 방식 선택에서는 **신세계포인트 통합회원 가입**만 다음 화면으로 이동하고, 나머지는 "프로토타입에서 준비 중" 안내가 뜹니다.

## 개선 포인트

등록된 이슈(#1~#7)를 기준으로 기존 가입 화면의 불편했던 점을 이렇게 바꿨습니다.

### 정보 입력

- **비밀번호 확인은 확실히 틀렸을 때만 오류** ([#1](../../issues/1))
  확인칸 값이 원래 비밀번호의 앞부분이면 아직 입력 중으로 보고 안내하지 않습니다. 확인칸을 벗어났는데 다르거나 길이를 넘겼을 때만 "일치하지 않아요"가 뜹니다.
- **우편번호 직접 입력 지원** ([#2](../../issues/2))
  숫자 5자리를 입력하면 바로 주소 검색 결과가 열립니다. Enter 키와 "주소 검색" 버튼으로도 검색할 수 있고, 숫자는 5자리를 넘지 않게 막습니다.
- **필수 정보 위주로 입력** ([#5](../../issues/5), 일부 반영)
  자택주소는 선택 항목이라 비워도 다음으로 넘어갑니다. 다만 주소 입력창이 아직 같은 화면에 있어서, 가입 후 별도 단계로 옮기는 작업이 남아 있습니다.

### 약관 동의

1. **필수와 선택을 한눈에 구분** ([#4](../../issues/4), [#3](../../issues/3))
   - 필수: 파란 테두리 + 왼쪽 굵은 파란 바 + 파란 `필수` 배지. 동의하면 행 전체가 연한 파랑으로 바뀝니다.
   - 선택: 회색 배경 + 얇은 테두리 + 회색 `선택` 배지.
   - 필수를 모두 동의하기 전에는 하단 버튼이 "필수 동의 N개 남았어요"로 비활성화됩니다.
   - 체크 부담은 **전체 동의하기** 하나로 줄였습니다. 선택 체크박스(서비스 9개, 마케팅 8칸)는 아직 많아서 접어 두거나 줄이는 방안은 결정이 필요합니다.
2. **마케팅 수신 동의는 한 곳에서, 결과는 한 번만** ([#6](../../issues/6))
   - 신세계포인트와 신세계면세점을 하나의 표로 합쳤습니다. 행은 이메일·문자·우편·전화, 열은 신세계포인트·신세계면세점이며 야간(21~08시) 수신은 면세점 한정입니다.
   - 표 아래 요약에서 채널별 `동의` / `미동의`가 바로 보입니다.
   - 기존의 결과 팝업 2개는 없애고, 가입 완료 화면의 **동의 현황 목록** 한 곳으로 합쳤습니다.
3. **통합 ID 서비스 한 번에 동의** ([#7](../../issues/7))
   - 맨 위 **전체 동의하기**로 필수 + 선택 항목을 한 번에 동의할 수 있습니다.
   - 서비스 9개(이마트, 신세계백화점, 신백멤버스, 신세계아울렛, 시코르, 이마트에브리데이, 신세계까사, 스타필드, 이마트24)는 "9개 서비스 한 번에 이용" 체크박스 하나로 묶었고, 서비스별 체크박스는 기존의 브랜드 색 바 UI를 유지하면서 높이를 줄였습니다.
4. **가입 완료 화면에서 확인·수정**
   - 필수 약관, 통합 ID 서비스 이용 수, 마케팅 채널별 동의/미동의, 변경일을 한 카드에서 보여 주고 "동의 내용 수정"으로 돌아갈 수 있습니다.

## 구조

```
.
├── index.html   # 전체 프로토타입 (화면 5개, CSS·JS 포함)
├── server.py    # 백엔드 (Python 표준 라이브러리 + SQLite)
├── gs-shop.md   # 디자인 토큰 명세
└── README.md
```

화면은 `entry → verification → info → consent → done` 순서로 `history` 기반으로 전환되며, 각 화면의 뒤로가기는 `history.back()`입니다.

## 다른 화면·서버와 연결하기

정보 입력 화면은 외부와 이어 붙일 수 있게 열어 두었습니다.

- `ShinInfo.config.checkIdAvailable(id)`: 아이디 중복확인. 지금은 시연용 목록으로 판단하며, 서버가 생기면 이 함수만 `fetch`로 바꾸면 됩니다.
- `ShinInfo.setVerified({ name, phone })`: 본인인증 결과를 넘겨 이름·휴대폰을 채웁니다. 값이 없으면 예시 값을 보여 줍니다.
- 입력 완료 시 `shin:info-complete` 이벤트(`detail`에 입력값)와, iframe 안이면 `postMessage`로 같은 내용을 보냅니다. 비밀번호는 `sessionStorage`에 저장하지 않습니다.

## 알려진 한계

- 필수 약관 3건(이용약관, 개인정보 수집·이용, 만 14세 이상)의 문구와 "보기" 약관 전문은 임의 값입니다. 실제 문구로 교체가 필요합니다.
- 서비스 브랜드 색과 로고 자리 텍스트는 기존 화면 캡처에서 눈대중으로 옮긴 값입니다.
